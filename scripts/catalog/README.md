# Сбор каталога из TMDB

Скрипт `scripts/catalog/` отбирает фильмы, забирает их метаданные из TMDB и складывает в JSON-файл
со списком фильмов, ключ фильма `movie_id`. Запись фильма - строка таблицы `movies` из
[контракта БД](https://github.com/dejaview-nsu/dejaview-docs/blob/main/contracts/db-schema.md#каталог-фильмов).
Основной БД в проекте пока нет, поэтому каталог живёт в файле. Видеофайлы скрипт не трогает.

## Запуск

Из корня репозитория, Python 3.11+:

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r scripts/catalog/requirements.txt
cp scripts/catalog/.env.example scripts/catalog/.env   # и вписать ключ TMDB
python -m scripts.catalog
```

Результат появляется в `scripts/catalog/output/movies.json`. Скрипт можно прервать (Ctrl+C) или запустить
повторно в любой момент: уже сохранённые фильмы заново не запрашиваются и не дублируются, работа продолжается
с места остановки. Фильмы, которые не загрузились из-за сбоя TMDB, повторяются при следующих запусках,
до трёх попыток. Два экземпляра скрипта с одной папкой результата одновременно не запускайте.

| Команда | Что делает |
|---|---|
| `python -m scripts.catalog` | собирает каталог до `CATALOG_TARGET_SIZE` фильмов и печатает отчёт |
| `python -m scripts.catalog --target 500` | то же с другой целью |
| `python -m scripts.catalog --report-only` | только отчёт о полноте данных, ключ TMDB не нужен |
| `python -m scripts.catalog -v` | подробный лог, включая причины отказа по каждому фильму |
| `python -m scripts.catalog --env-file path/.env` | другой файл окружения |

Коды выхода: `0` цель достигнута, `1` сбой TMDB или записи на диск, `2` ошибка настроек, ключа TMDB
или повреждённый файл результата, `3` цель не достигнута, `130` прервано пользователем.

## Переменные окружения

Читаются из `scripts/catalog/.env`, переменные окружения процесса важнее файла. `.env` в git не коммитится.

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `TMDB_ACCESS_TOKEN` | одна из двух | | API Read Access Token TMDB, предпочтительный способ |
| `TMDB_API_KEY` | одна из двух | | API Key (v3) TMDB |
| `CATALOG_TARGET_SIZE` | нет | `1000` | сколько фильмов должно оказаться в каталоге |
| `CATALOG_MIN_VOTE_COUNT` | нет | `200` | минимум голосов на TMDB: отсекает безвестные фильмы без метаданных |
| `CATALOG_YEAR_FROM` | нет | `1950` | с какого года выпуска отбирать фильмы |
| `TMDB_REQUESTS_PER_SECOND` | нет | `20` | ограничение частоты запросов к TMDB, не больше 50 |
| `CATALOG_OUTPUT_DIR` | нет | `scripts/catalog/output` | папка для `movies.json` и `candidates.json` |
| `CATALOG_PRIORITY_IDS_FILE` | нет | | файл с movie_id фильмов, которые берутся первыми, см. [Приоритетные фильмы](#приоритетные-фильмы) |

## Как отбираются фильмы

1. Первыми идут приоритетные фильмы из ручного списка, см. [ниже](#приоритетные-фильмы).
2. Остальные берутся из TMDB `/discover/movie` по корзинам «жанр × десятилетие», в каждой самые известные
   первыми, и перемешиваются по кругу. Так каталог не состоит из одних свежих блокбастеров.
3. В каталог не попадают фильмы без постера, без русского названия или без русского описания.
   Русское название проверяется по переводам TMDB: TMDB подставляет оригинальное название, если перевода нет.

На фильм уходит один запрос: детали, `credits`, `release_dates` и `translations` приходят вместе через
`append_to_response`. Ещё один запрос за запуск - справочник стран `/configuration/countries` ради русских названий.
Постер и фото актёров хранятся путём на CDN TMDB (`/abc.jpg`), файлы не скачиваются.

## Приоритетные фильмы

Сюда стоит вписывать фильмы, исходное видео которых точно можно достать: каталог без возможности
проиндексировать фильм поиску бесполезен. Такие фильмы обрабатываются раньше всех остальных.

**1. Найдите movie_id.** Откройте фильм на [themoviedb.org](https://www.themoviedb.org) и возьмите число
из адреса страницы: `https://www.themoviedb.org/movie/550-fight-club` → `550`.

**2. Впишите его в файл** `scripts/catalog/priority_ids.txt`, по одному на строку. После `#` можно
оставить комментарий, пустые строки и повторы пропускаются:

```
# Фильмы, для которых есть видео
550      # Бойцовский клуб
603      # Матрица
```

**3. Укажите файл в `scripts/catalog/.env`.** Относительный путь считается от корня репозитория,
откуда запускается скрипт:

```
CATALOG_PRIORITY_IDS_FILE=scripts/catalog/priority_ids.txt
```

**4. Запустите сбор**, как обычно: `python -m scripts.catalog`. В логе появится строка
`Приоритетных фильмов в списке: N`, затем по строке на каждый сохранённый фильм.

Файл перечитывается при каждом запуске, так что список можно пополнять когда угодно: новые фильмы
встанут в начало очереди, а уже обработанные заново не запрашиваются. Файл не секретный, его можно
закоммитить, чтобы у всей команды был общий список.

> **Если каталог уже набрал `CATALOG_TARGET_SIZE`**, скрипт сразу завершается и новые фильмы из списка
> не загружает. Поднимите цель на число добавленных фильмов, например `python -m scripts.catalog --target 1050`.

### Если фильм не попал в каталог

Приоритетные фильмы проходят те же критерии отбора, что и остальные. Причину отказа покажет запуск
с `-v` (строка `Фильм 603 отклонён: no_russian_title`), она же записана в `output/candidates.json`
в поле `reject_reason` у записи с нужным `movie_id`.

| Причина | Что значит | Что делать |
|---|---|---|
| `not_found` | в TMDB нет фильма с таким id | проверьте число в адресе страницы |
| `no_russian_title` | у фильма в TMDB нет русского названия | дополнить перевод на TMDB или выбрать другой фильм |
| `no_russian_overview` | нет русского описания сюжета | то же |
| `no_poster` | нет постера | то же |
| `adult` | фильм помечен как контент для взрослых | такие фильмы в каталог не берутся |

Если фильм не загрузился из-за сбоя сети или TMDB, скрипт сам повторит его при следующих запусках, до трёх попыток.
Ошибка в самом файле, например буквы вместо числа, останавливает запуск до обращения к TMDB,
а в сообщении указаны файл и номер строки: `priority_ids.txt:3: ожидался положительный movie_id`.

## Что получается на выходе

`movies.json`: список фильмов, отсортированный по `movie_id`. Ключи записи - колонки таблицы `movies`
из [контракта](https://github.com/dejaview-nsu/dejaview-docs/blob/main/contracts/db-schema.md#каталог-фильмов),
так что файл загружается в БД построчно через `INSERT ... ON CONFLICT (movie_id) DO UPDATE`. Пример записи:

```json
{
  "movie_id": 550,
  "title": "Бойцовский клуб",
  "original_title": "Fight Club",
  "release_date": "1999-10-15",
  "age_rating": "18+",
  "poster_path": "/66RvLrRJTm4J8l3uHXWF09AICol.jpg",
  "runtime_min": 139,
  "overview": "Сотрудник страховой компании страдает хронической бессонницей...",
  "genres": [{"id": 18, "name": "драма"}, {"id": 53, "name": "триллер"}],
  "countries": [{"code": "DE", "name": "Германия"}, {"code": "US", "name": "Соединенные Штаты"}],
  "crew": [
    {"person_id": 7467, "name": "Дэвид Финчер", "role": "director"},
    {"person_id": 7469, "name": "Джим Улс", "role": "writer"},
    {"person_id": 7477, "name": "John King", "role": "composer"},
    {"person_id": 1254, "name": "Art Linson", "role": "producer"}
  ],
  "actors": [
    {"person_id": 819, "name": "Эдвард Нортон", "character": "Narrator", "profile_path": "/8nytsqL59SFJTVYVrN72k6qkGgJ.jpg"}
  ],
  "cached_at": "2026-09-29T04:11:50+00:00"
}
```

- `title`: русское название, без него фильм в каталог не попадает.
- `release_date`, `age_rating`, `runtime_min`: `null`, если в TMDB не заполнены. `age_rating` - 0+/6+/12+/16+/18+,
  только российский рейтинг.
- `poster_path`: путь на CDN TMDB, URL с нужным размером собирает backend.
- `countries`: код ISO 3166-1 и русское название из справочника TMDB. Если русского нет, например у `SU`,
  остаётся английское.
- `crew`: режиссёры, сценаристы, композиторы, продюсеры в этом порядке. Человек с двумя ролями встречается дважды.
- `actors`: до 30 человек в порядке титров, `character` и `profile_path` могут быть `null`.
- `cached_at`: когда метаданные получены из TMDB, UTC. `indexed_at` скрипт не пишет, его ставит индексация.
- Пустые списки - `[]`, пустых строк нет.

Если `movies.json` собран версией скрипта со старым форматом записи, запуск остановится с ошибкой
«поля не совпадают с таблицей movies». Удалите папку `output/` и соберите каталог заново.

`candidates.json`: служебная очередь отбора со статусом и причиной отказа по каждому рассмотренному фильму.
За счёт неё работает продолжение после обрыва. Удалите её, если нужно начать отбор заново,
при этом уже собранные фильмы в `movies.json` сохранятся.

Оба файла пишутся атомарно, через временный файл, так что обрыв посреди записи их не портит.
Промежуточное сохранение идёт каждые 20 изменений и при любом завершении, включая Ctrl+C.
Папка `output/` в `.gitignore`: где хранить готовый каталог, решает команда.

## Устройство

```
scripts/catalog/
├── cli.py, config.py   запуск и настройки
├── importer.py         основной цикл: очередь -> TMDB -> каталог
├── report.py           отчёт о полноте данных
├── tmdb/               клиент TMDB, ограничение частоты запросов
├── movies/             запись каталога, разбор ответа TMDB, критерии отбора
├── candidates/         очередь отбора, поиск кандидатов в TMDB, ручной список
├── storage/            хранение в JSON
└── tests/              тесты, все в одном каталоге
```

Зависимости идут сверху вниз: `tmdb` и `movies` ничего не знают об очереди и хранении.
Всё, что относится к скрипту, лежит в `scripts/catalog/`: зависимости, настройки ruff и pytest
(`pyproject.toml`), `.gitignore` для `output/`.

## Отчёт о полноте данных

В конце каждого запуска и по `--report-only` скрипт печатает, у скольких фильмов пусты те или иные поля
и сколько кандидатов отсеяно по каждой причине.

## Тесты

Из корня репозитория:

```bash
pip install -r scripts/catalog/requirements-dev.txt
pytest scripts/catalog
ruff check scripts/catalog && ruff format --check scripts/catalog
```
