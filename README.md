# dejaview-ml

Эмбеддинги запросов и фильмов, векторный поиск, индексация каталога.

## Зона ответственности

- Эмбеддинги по модальностям: текст, изображение, кадры видео, аудио
- Нарезка видео на кадры и сегменты, аудио на чанки
- Векторный поиск в Qdrant и замеры качества выдачи по каждому режиму
- Подготовка и обновление индекса каталога
- Офлайн-скрипты: сбор каталога из TMDB (`scripts/catalog/`), индексация фильма (`scripts/index/`)

## Стек

- Python, HuggingFace
- Qdrant, четыре коллекции по модальностям
- Модели и размерности заданы требованием, таблица в `dejaview-docs/architecture.md`
- Веса моделей кэшируются между перезапусками и в репозиторий не коммитятся

## Сбор каталога из TMDB

Скрипт `scripts/catalog/` отбирает фильмы, забирает их метаданные из TMDB и складывает в JSON-файл
со списком фильмов, ключ фильма `movie_id`. Основной БД в проекте пока нет, поэтому каталог живёт в файле. Видеофайлы скрипт не трогает.

### Запуск

Из корня репозитория, Python 3.11+:

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r scripts/catalog/requirements.txt
cp scripts/catalog/.env.example scripts/catalog/.env   # и вписать ключ TMDB
python -m scripts.catalog
```

Результат появляется в `scripts/catalog/output/movies.json`. Скрипт можно прервать (Ctrl+C) или запустить
повторно в любой момент: уже сохранённые фильмы заново не запрашиваются и не дублируются, работа продолжается
с места остановки. Фильмы, которые не загрузились из-за сбоя TMDB, повторяются при следующих запусках,
до трёх попыток. Два экземпляра скрипта с одной папкой результата одновременно не запускайте.

| Команда | Что делает |
|---|---|
| `python -m scripts.catalog` | собирает каталог до `CATALOG_TARGET_SIZE` фильмов и печатает отчёт |
| `python -m scripts.catalog --target 500` | то же с другой целью |
| `python -m scripts.catalog --report-only` | только отчёт о полноте данных, ключ TMDB не нужен |
| `python -m scripts.catalog -v` | подробный лог, включая причины отказа по каждому фильму |
| `python -m scripts.catalog --env-file path/.env` | другой файл окружения |

Коды выхода: `0` цель достигнута, `1` сбой TMDB или записи на диск, `2` ошибка настроек, ключа TMDB
или повреждённый файл результата, `3` цель не достигнута, `130` прервано пользователем.

### Переменные окружения

Читаются из `scripts/catalog/.env`, переменные окружения процесса важнее файла. `.env` в git не коммитится.

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `TMDB_ACCESS_TOKEN` | одна из двух | | API Read Access Token TMDB, предпочтительный способ |
| `TMDB_API_KEY` | одна из двух | | API Key (v3) TMDB |
| `CATALOG_TARGET_SIZE` | нет | `1000` | сколько фильмов должно оказаться в каталоге |
| `CATALOG_MIN_VOTE_COUNT` | нет | `200` | минимум голосов на TMDB: отсекает безвестные фильмы без метаданных |
| `CATALOG_YEAR_FROM` | нет | `1950` | с какого года выпуска отбирать фильмы |
| `TMDB_REQUESTS_PER_SECOND` | нет | `20` | ограничение частоты запросов к TMDB, не больше 50 |
| `TMDB_POSTER_SIZE` | нет | `w500` | размер постера в ссылке на CDN TMDB: `w92`...`w780` или `original` |
| `CATALOG_OUTPUT_DIR` | нет | `scripts/catalog/output` | папка для `movies.json` и `candidates.json` |
| `CATALOG_PRIORITY_IDS_FILE` | нет | | файл с movie_id фильмов, которые берутся первыми |

### Как отбираются фильмы

1. Первыми идут фильмы из `CATALOG_PRIORITY_IDS_FILE`: сюда стоит вписать фильмы, исходное видео которых
   точно можно достать. Формат: один movie_id TMDB на строку, после `#` комментарий.
2. Остальные берутся из TMDB `/discover/movie` по корзинам «жанр × десятилетие», в каждой самые известные
   первыми, и перемешиваются по кругу. Так каталог не состоит из одних свежих блокбастеров.
3. В каталог не попадают фильмы без постера, без русского названия или без русского описания.
   Русское название проверяется по переводам TMDB: TMDB подставляет оригинальное название, если перевода нет.

На фильм уходит один запрос: детали, `credits` и `release_dates` приходят вместе через `append_to_response`.
Постер хранится ссылкой на CDN TMDB, файл не скачивается.

### Что получается на выходе

`movies.json`: список фильмов, отсортированный по `movie_id`. Пример записи:

```json
{
  "movie_id": 550,
  "title_ru": "Бойцовский клуб",
  "original_title": "Fight Club",
  "release_date": "1999-10-15",
  "age_rating": "18+",
  "poster_url": "https://image.tmdb.org/t/p/w500/pB8BM7pdSp6B6Ih7QZ4DrQ3PmJK.jpg",
  "overview_ru": "Сотрудник страховой компании страдает хронической бессонницей...",
  "runtime_minutes": 139,
  "country_codes": ["US", "DE"],
  "genres": ["драма", "триллер"],
  "directors": [{"person_id": 7467, "name": "David Fincher"}],
  "writers": [{"person_id": 7468, "name": "Jim Uhls"}],
  "composers": [{"person_id": 1060, "name": "Dust Brothers"}],
  "producers": [{"person_id": 7474, "name": "Art Linson"}],
  "actors": [{"person_id": 819, "name": "Edward Norton", "character": "The Narrator"}]
}
```

- `age_rating`: 0+/6+/12+/16+/18+ или `null`, если в TMDB нет российского рейтинга.
- `release_date`, `runtime_minutes`: `null`, если в TMDB не заполнены.
- `country_codes`: коды ISO 3166-1, потому что TMDB отдаёт названия стран только по-английски.
- `actors`: до 30 человек в порядке титров.

`candidates.json`: служебная очередь отбора со статусом и причиной отказа по каждому рассмотренному фильму.
За счёт неё работает продолжение после обрыва. Удалите её, если нужно начать отбор заново,
при этом уже собранные фильмы в `movies.json` сохранятся.

Оба файла пишутся атомарно, через временный файл, так что обрыв посреди записи их не портит.
Промежуточное сохранение идёт каждые 20 изменений и при любом завершении, включая Ctrl+C.
Папка `output/` в `.gitignore`: где хранить готовый каталог, решает команда.

### Устройство

```
scripts/catalog/
├── cli.py, config.py   запуск и настройки
├── importer.py         основной цикл: очередь -> TMDB -> каталог
├── report.py           отчёт о полноте данных
├── tmdb/               клиент TMDB, ограничение частоты запросов
├── movies/             запись каталога, разбор ответа TMDB, критерии отбора
├── candidates/         очередь отбора, поиск кандидатов в TMDB, ручной список
└── storage/            хранение в JSON
```

Зависимости идут сверху вниз: `tmdb` и `movies` ничего не знают об очереди и хранении.

### Отчёт о полноте данных

В конце каждого запуска и по `--report-only` скрипт печатает, у скольких фильмов пусты те или иные поля
и сколько кандидатов отсеяно по каждой причине.
